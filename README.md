# Atto XO · Marketing site

The public-facing Atto XO marketing website, now built with **Astro** instead of Jekyll, Hugo, or a hand-maintained root `index.html`.

**Brand:** atto x💙 — the royal-blue heart stands in for the “o” in XO.

**Product:** Atto XO is an early-stage, Rust-first trading research and decision-support platform for **human traders**. The intended research pipeline uses **nonlinear regression models** to investigate intraday signals and **MIP/MILP optimization** to evaluate feasible trade selections, sizing, and hard risk constraints. Paper recommendations come first; real-money brokerage execution is not enabled or advertised by this site.

## Local development

Requires Node.js 22.12+ (CI uses Node 24).

```bash
npm install
npm run dev
npm run build
npm test
npx playwright install chromium
npm run test:e2e
```

Astro emits static pages to `dist/`. No server-side runtime or secrets are required. `npm test` and `npm run test:e2e` expect `npm run build` first. Browser tests use Chromium and a local `astro preview` server and exercise responsive layouts, keyboard navigation, risk disclosure, and automated axe WCAG checks. The size budget checks emitted first-party assets, rather than treating lab timings as production measurements.

### Pages deployment

The GitHub Actions workflow in `.github/workflows/site.yml` verifies the website on pull requests and deploys `dist/` after a successful build on `main`.

1. In repository **Settings → Pages**, choose **GitHub Actions** as the build/deployment source.
2. Confirm that Pages is enabled for this public repository, with **GitHub Actions** selected as the publishing source.
3. Merge the marketing site PR after the build and content checks pass.
4. Confirm that `https://atto-xo.github.io/` resolves and review the live mobile/desktop page.

Because the repository name is `atto-xo.github.io`, Astro's `site` is `https://atto-xo.github.io` and no repository subpath (`base`) is needed. The build is intentionally **not** a Jekyll/Hugo pipeline.

Dependencies are committed in `package-lock.json`, generated by trusted GitHub Actions npm resolution (Node 24.22.2, npm 11.19.1) and captured from run [42897447592](https://github.com/atto-xo/atto-xo.github.io/actions/runs/42897447592), SHA-256 `ef3d20cadb0c8d76f245b4568ca81e43f8b901a8a39e9761fd2ce8e3cf59c454`. CI verifies `tools/lockfile.sha256` and uses `npm ci` so changed lockfiles or mismatched dependencies fail closed. Browser tests run on the resolved version from the lockfile. Review dependency changes before updating it.

### Deployment safeguards

Pull requests build and test without publishing. Artifact upload and deployment require `refs/heads/main`, including manually dispatched runs. Checkout does not persist repository credentials in the runner workspace, and all four first-party workflow actions are pinned to reviewed commit SHAs. A green CI run does not replace a review of public claims and disclosures.

## Copy standards and design principles

- Never advertise measured returns, outperforming benchmarks, guaranteed profitability, or live model signals without independently reviewed evidence.
- Label illustrative dashboard curves and candidate cards as simulated/conceptual.
- Treat the proposed **10-minute** cycle, **8-minute** publishing window, and cap of **five** ranked candidates as **design targets**, not validated operating service levels.
- Distinguish what a nonlinear model estimates from what a MIP/MILP optimizer allows under budget and risk constraints.
- Human traders retain decision authority; execution would require its own authorization, security review, and product gating.
- Never bundle API keys, private research data, client positions, credentials, or financial records into public static assets.

## Interactive research demonstration

The static `/research-demo/` route provides a **synthetic, educational** illustration of the model → optimize → decide workflow. Nine invented observations are fitted by a quadratic least-squares model; the illustrative extrapolation is not a forecast. Candidate costs, scores, and downside units are fictional and independent of the curve. A bounded enumeration (48 combinations) chooses a maximum-score feasible integer allocation under adjustable hard constraints, with deterministic tie-breaking. This illustrates a tiny mixed-integer optimization problem but **is not a production MILP solver**.

The demo requires no account, API, server, credentials, network feed, trade execution, or data collection. Pure model/optimizer tests check fitting correctness and exhaustively compare optimality and feasibility across a parameter grid. Playwright tests cover the demo at desktop and mobile widths, slider interactions, WCAG A/AA, and outbound request restrictions.

Do not use the synthetic output as trading guidance or describe the mock score as a return or backtested result.


## Browser QA evidence

The verify job retains Playwright browser screenshots and single-navigation timing diagnostics for seven days in the `atto-xo-browser-evidence-*` workflow artifact, across all configured desktop/mobile widths. These are review artifacts, **not** Lighthouse scores, Core Web Vitals field measurements, or performance guarantees. CI also checks canonical and social metadata, sitemap parity, internal links, and the absence of remote script tags.

A raster social card is provided; compatibility with third-party social sharing platforms must still be checked after release.

### Public architecture explanation

The `/architecture/` page describes intended Rust-first research workflow boundaries: point-in-time inputs, modeling, hard risk constraints, integer candidate selection, explainability, and human approval. These are **design contracts, not implemented production performance claims**. It links to the educational synthetic demo and the Atto XO RFC repository (some repositories may need access).


### Cross-browser E2E gate

GitHub Actions runs the existing accessibility, risk-disclosure, navigation and synthetic-optimization browser tests in **Chromium** (desktop, 390px and 320px mobile), **Firefox** (desktop), and **WebKit** (desktop). Browser engines are installed via the lockfile-pinned Playwright CLI and Linux packages; no third-party brokerage access is required. Screenshot evidence is retained per Playwright project with a bounded 7-day artifact lifetime. Cross-browser engine execution is a regression check, not formal screen-reader or native-device certification.


## Explainable synthetic research demo v2

The research demo now provides three fictional constraint scenarios, forced-inclusion explanations of candidate exclusions (reoptimizing the entire bounded allocation), overlapping constraint-violation counts, sensitivity checks, and a JSON report generated locally in the browser. The report is deterministic and timestamp-free, contains only static invented observations, constraints, scores, and diagnostics, and explicitly disclaims market data or financial advice. It is not a production MILP optimizer or a live trading service.


### Visual regression baseline hardening

The test suite captures full viewport PNG screenshots of the homepage, architecture page and three research-demo states in Chromium desktop/mobile/320px, Firefox, and WebKit. CI compares a committed coarse 20×12 RGB grid fingerprint for each engine/state (25 fingerprints) using defined color-difference tolerances; full screenshots and machine-readable comparisons are retained as review artifacts. The grid detects broad layout and palette regressions, not tiny glyph changes and **not** pixel-perfect visual equality. Baseline refreshes are explicit, never automatically accepted on ordinary PR CI.
